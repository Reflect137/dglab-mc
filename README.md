# 掉血加电 · 《我的世界》× DG-LAB 郊狼

> **血扣得越多，电给得越多。**
> 你在游戏里挨打 → 郊狼强度按伤害量往上顶，同时打出一段波形；停手一会儿强度自动回落，死亡立即归零。

原材料来自工作区里的三份东西：

| 来源 | 用到了什么 |
|---|---|
| `API/`（游戏 JS ModAPI v2 文档） | `onEntityBehaviorEvent(id, 2)`（受伤动画）、`onTickEvent`（20 刻/秒）、`Actor.getAttribute("minecraft:health")`、`require("socket")` 的 WebSocket、`require("sp")` 存档、`onImGuiRenderEvent` 画面板 |
| `dglab-websocket-server-main (1).zip` | V3 中继协议的**权威实现**，本仓库的 `tools/dglab-relay.js` 逐条对齐它 |
| `dglab-kit-main.zip` | V3 帧格式与用法（`type:3` / `clientMsg` / `clear`），以及 11 组郊狼波形数据 |

## 2. 已在官方服务器上验证过

除了本地自测，这份实现还和**官方生产服务器 `wss://ws.dungeon-lab.cn/`** 做过一次真实比对（模拟「控制端 + APP 端」两个连接，不下发任何真实设备指令）：

| 环节 | 官方服务器实际行为 | 本仓库的实现 |
|---|---|---|
| 握手 | `{"type":"bind","clientId":"<uuid>","targetId":"","message":"targetId"}` | 一致 |
| APP 接入 | 双方各收到 `{"type":"bind","clientId":"<控制端>","targetId":"<APP>","message":"200"}` | 一致 |
| 强度指令 | `{type:3, channel:"A", strength:N}` → APP 收到 `strength-1+2+N` | 一致（脚本用的是 `set channel`） |
| 波形 | `{type:"clientMsg", channel:"A", message:"A:[...]"}` → APP 收到 `pulse-A:[...]` | 一致（**前缀是通道字母**） |
| APP 回传 | `strength-A+B+上限A+上限B` 原样转给控制端 | 一致（脚本按此解析） |

所以脚本把「中继地址」改成官方地址也能直接用：

```text
!dg set relayUrl wss://ws.dungeon-lab.cn/
!dg connect
!dg pair
```

## 3. 它是怎么跑起来的

```text
 ┌─────────────────── 同一台安卓手机 ───────────────────┐
 │                                                      │
 │  《我的世界》+ dglab-hp.js        DG-LAB APP         │
 │      （控制端）                    （被控方）          │
 │          │  ws://127.0.0.1:9999/?cid=mc-coyote        │
 │          │                            │               │
 │          └──────► dglab-relay.js ◄────┘               │
 │                   ws://127.0.0.1:9999/mc-coyote       │
 │                   （Termux 里跑）                      │
 └──────────────────────────────────────────────────────┘
```

* 游戏脚本是 **V3 控制端**：拿 `clientId` → 等 APP 接入 → 下发强度和波形。
* 中继只做配对和转发（`?cid=` 是本仓库给中继加的扩展，让配对地址固定成 `mc-coyote`，不用每次重新输入）。
* APP 侧就是 DG-LAB 的「Socket 控制」，连接 `ws://127.0.0.1:9999/mc-coyote`。

```

### 第 2 步：把 `dglab-hp.js` 放进游戏

把 `dglab-hp.js` 放到你模组的脚本目录（和别的 JS 脚本同级），用你平时的加载方式加载它（有的环境是脚本自动加载，有的需要 `runScript("dglab-hp")`）。

脚本加载后会打印一行日志：

```text

```

### 第 3 步：DG-LAB APP 连上来

进游戏后，聊天栏输入：

```text
!dg pair
```

会得到两个提示：

```text
[掉血加电] ① APP 手动输入地址: ws://127.0.0.1:9999/mc-coyote
[掉血加电] ② 要扫码就把这行丢到别的设备生成二维码: https://www.dungeon-lab.com/app-download.php#DGLAB-SOCKET#...
```

* **APP 能手动填地址** → 直接用 ①。
* **APP 只能扫码** → 把 ② 复制到另一台设备（电脑/平板）打开生成二维码，再用 APP 扫。

配对成功后聊天栏会提示：

```text
[掉血加电] APP 已连接 ✅ 当前强度 0，可以开打了
```

**第一次务必先试小的**：

```text
!dg set 每点伤害加电 1
!dg test 3
```

`!dg test 3` 会用手动强度放 3 秒波形，先确认贴在身上的电极位置、强度手感都正常，再去挨打。

## 5. 加电是怎么算的

```text
受伤 D 点血（1 点 = 半颗心）
  曲线 = 伤害换算曲线（线性 / 平方 / 开方）
  倍率 = 重击倍率 × 低血倍率 × 连击倍率（都可开关）
  电量 += 曲线(D) × 每点伤害加电 × 倍率      ← 瞬间到位，不做渐变
        （受 单次最多加电 / 每秒最多加电 / 电量上限 三重限制）
  波形时长 = 1 秒 + D × 0.5 秒（最长 8 秒）；电量没清就一直续
  强度 = 基础强度 + 电量（不超过强度上限）

电量只在回血时下降（默认「回满血才清」）
  没回满血  → 电量保持不变，一直放电
  回满血    → 电量清零、强度归零、波形清掉
  另有「按回血比例减」和「比例减但保底」两种模式；「没过满时电量保底」>0 就是强制一直电
  兜底：血量一直满着（例如黄心被打掉、瞬间回满）超过「满血判定延迟」也会自动清电

死亡
  默认「电量拉满」：电量顶到上限、强度瞬间到位、放 3 秒波形
  可改成「立即归零」或「不处理」

归零 / 暂停 / 关闭 / 退出世界
  左右两路（A、B）同时强度 0 + 清波形，不留残值
  手动归零后进入「归零后静默」（默认 1.5 秒），这段时间挨打不会再被加回来
  暂停期间受伤完全不加电、也不下发（不会出现「归零无效」）
```

双路（同时启用 A、B）：

| 设置 | 说明 |
|---|---|
| 控制通道 = 双路 A+B | 两路同时输出 |
| 右路强度倍率 | 右路 = 左路 × 倍率（0.5 = 一半） |
| 右路强度偏移 | 右路再加减一个固定值（可为负） |
| 右路波形 | 右路可以单独用另一种波形（默认跟随主波形） |

## 9. 安全须知（请务必看）

* **先小后大**：第一次用把「每点伤害加电」设成 `1`、`强度上限` 设成 `10` 以内，`!dg test 3` 试手感，再慢慢加。
* **`强度上限` / `每秒最大涨幅` 是安全阀**，不要为了刺激调到很大；DG-LAB APP 自己还有一层「舒适强度上限」，实际输出会被它再限一次。
* **`!dg stop` 是紧急按钮**：立即下发强度 0 并清空波形，同时暂停后续触发。退出世界也会自动归零。
* **电极别贴在心脏位置、脖子、头部**；有心脏疾病、癫痫、体内电子植入物者不要使用；不要一个人玩到无法自己摘设备。
* 游戏里 **饥饿、中毒、着火、摔落、溺水都会算伤害**，觉得吵就把 `minDamage` 调高（例如 2 = 一颗心以下不算）。
* 中继断开时，APP 那侧也会被中继断开（V3 协议如此），此时脚本会自动重连中继，APP 里可能需要重新连一次。

## 10. 常见问题

**Q：`!dg pair` 说「还没连上中继」**
A：Termux 里的中继没起来，或者端口不对。检查中继窗口有没有 `[relay] listening`；游戏侧 `!dg set relayUrl ws://127.0.0.1:9999/` 确认地址一致。

**Q：中继起来了，游戏里也显示等待 APP，但 APP 连不上**
A：中继连接的地址要和 `!dg pair` 输出的**完全一致**（默认 `ws://127.0.0.1:9999/mc-coyote`）。`mc-coyote` 就是脚本里 `controllerId` 的值，改了它地址也会跟着变。也可以浏览器打开 `http://127.0.0.1:9999/__status` 看当前连接数和配对数。

**Q：能配对，但身上没感觉**
A：三个可能——① 电极没贴好/没插好（郊狼主机上通道灯的状态能看出来）；② 强度太低（先 `!dg status` 看「已下发」的数字，再用 `!dg test 5` 手动试）；③ `burstEnabled` 被关了，只发强度不发波形，设备不会输出。

**Q：太疼 / 太吵**
A：`!dg set 每点伤害加电 1`、`!dg set 强度上限 10`、`!dg set 每秒最大涨幅 3`；还是吵就 `!dg set 最小伤害 2`（一颗心以下不计）。

**Q：只想要「掉血瞬间一下」，不想持续**
A：`!dg set 受伤后保持 0`、`!dg set 每秒回落电量 20`、`!dg set 波形基础时长 1`、`!dg set 每点伤害加时长 0`。

**Q：想换回官方服务器（不用 Termux）**
A：把中继地址改成官方 V3 地址即可：

```text
!dg set relayUrl wss://ws.dungeon-lab.cn/
!dg connect
!dg pair
```

这时 `controllerId` 会被官方服务器忽略，`!dg pair` 会显示随机分配的配对地址，用那个地址扫码/输入。

**Q：想让端口固定/换端口**
A：`bash tools/start-termux.sh 12345`，游戏里同步 `!dg set relayUrl ws://127.0.0.1:12345/`。

**Q：中继能不能多开/多人用**
A：V3 是 1 控制端 : 1 APP。一个中继端口可以同时服务多组配对（不同的 `clientId`），但每个 `controllerId` 要唯一。

## 11. 已知限制

* 血量是从**客户端**读的，网络延迟大时伤害检测会有几十毫秒误差；`pollEveryTicks=1` 时约 50ms 一次。
* **无法区分伤害来源**：目前只能拿到「掉了多少血」，拿不到「被什么打的」（客户端事件里没有伤害原因）。想按来源区分就得改服务端 Python 模组并通过 PyRpc 转发给客户端脚本。
* 创造/旁观模式默认不触发（可关）。
* 波形在「保持期」内会持续续播，每段最长 `burstMaxSec` 秒；续播是上一段播完后立刻接上，衔接处可能有 ~100ms 的空档。
* 面板控件的函数签名依赖游戏版本，脚本做了多签名兼容，极端情况下会退化成文字 + 按钮。

### 协议里踩到的两个坑（写脚本的人注意）

1. **强度指令的 `message` 不能以 `strength` 开头**（别写 `"strength"`）。中继/服务端会先判断「是不是 APP 回传」，`strength` 开头的一律当回传直接透传，不会转成 `strength-<通道号>+2+<值>`。官方 SDK 用的是 `"set channel"`，本脚本也用它。
2. **波形包前缀是通道字母**：`pulse-A:[...]` / `pulse-B:[...]`；而强度、清除用的是通道号：`strength-1+2+20`、`clear-1`。两者不要混。
